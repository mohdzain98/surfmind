Description

Evaluates maintainability signals across modules and functions, with emphasis on complexity and long-term edit risk.

Observability

Quality Categories

  • Logging coverage
  • Critical function instrumentation
  • Monitoring and exception visibility

Description

Checks runtime visibility so incidents can be diagnosed and traced with less ambiguity.

What it finds

  • Missing logs in critical functions
  • Low coverage of observability across files
  • Unstructured or weak instrumentation practices

Tools used

  • AST scanning rules
  • internal heuristic analysis
Severity Focus
Severity Description Example Code
High Critical observability gaps that can hide production failures or block debugging. These include missing logs in critical functions or overall observability score below threshold. Overall observability score < 30, critical function without logging
Medium Files or modules with insufficient logging or limited instrumentation, reducing incident traceability. Files with Poor Observability
Low Logging is present but not structured or standardized, making correlation and deep analysis harder. Missing Structured Logging
Info Files with fair observability that meet minimum standards but can still benefit from richer logs. Files with Fair Observability
What is a Critical Function?
Term Meaning
Critical Function Any function that includes patterns like error/exception handling, authentication/authorization, processing, validation, or functions with try/except/raise usage. These functions are expected to emit logs because failures here have higher observability impact.
